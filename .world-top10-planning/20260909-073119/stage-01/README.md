# STAGE-1-BASELINE — 기준선·안전 기반

## 1. 쉬운 말 한 문장 목표

현행 파악·자료 보존·개발환경·안전 기반를 한 문장으로 확인한다.

## 2. 사용자에게 보이는 단계 완료 모습

현재 공개 URL·미검증 경계·재현 명령이 한 화면에 보임

## 3. 포함 범위

TASK-001, TASK-002, TASK-003, TASK-004와 이 단계의 증거·시험·복구 문서

## 4. 명시적 제외 범위와 이유

실제 음원 생성, 비밀값 입력, 결제, 외부 연락, 공개판 변경은 계획 범위에서 제외한다.

## 5. 진입 조건 체크리스트

[ ] 프로젝트 식별 완료  [ ] 이전 단계 증거 링크  [ ] 작업 폴더 경계

## 6. 이전 단계에서 받는 입력

현재 PRD·DEVPLAN·공개 검증 기록

## 7. 산출물 파일 목록

## 9. 작업 의존 관계와 실행 순서

TASK-001 → TASK-002 → TASK-003 → TASK-004

## 10. 병렬 실행 가능 작업

문서 읽기, JSON 파싱, 정적 검사만 병렬 실행한다.

## 11. 절대 순차 실행 작업

진입 조건 확인 → 작업 → 시험 → 증거 → 종료 판정 순서를 지킨다.

## 12. 예상 변경 파일·기호·설정

분석 폴더 안의 stage 파일만 생성하며 제품 코드·배포 설정은 바꾸지 않는다.

## 13. 데이터·API·UI 계약 변화

계획 계약만 문서화하고 운영 API 성공으로 표시하지 않는다.

## 14. 정상 흐름

체크리스트가 모두 참이면 다음 작업으로 이동한다.

## 15. 빈·로딩·부분 성공 흐름

값이 없으면 null/미검증과 확인 명령을 함께 기록한다.

## 16. 실패·권한 거부·오프라인·복구 흐름

BLOCKED_EXTERNAL로 기록하고 기존 공개판을 유지한다.

## 17. 접근성·다국어·모바일·PC 조건

한국어 쉬운 문구, 390/1280 폭, 키보드, 모바일을 시험 목록에 포함한다.

## 18. 보안·개인정보·권한 조건

secret·토큰·store_id·기기 식별자를 산출물에 넣지 않는다.

## 19. 성능·용량·비용 예산

외부 비용 0; 명령별 종료값과 파일 크기를 기록한다.

## 20. 자동 시험 묶음

TEST-001, TEST-013, TEST-025, TEST-037부터 연결

## 21. 수동·실기기·외부 서비스 시험 묶음

실기기·OAuth·PG·DB는 외부 증거가 있을 때만 수행한다.

## 22. 중단 신호와 되돌리는 순서

오래된 문서를 현재 운영 상태로 오인 발견 시 즉시 중단 → 로그 보존 → 새 폴더 격리 → 기존판 유지

## 23. 종료 조건과 필요한 증거

정본·범위·백업·실행·검사 기준선 재현 가능; 증거 파일과 명령 종료값이 모두 있어야 한다.
